## A. Syn2bANI 论文（`manuscript_nature_methods.md`）

### A1 [致命] 结构变异案例研究全部基于修复前的 `breakpoint_count`

证据链：

- `Syn2bANI/src/core/chain_ani.rs:857-865` 的文档注释自述：修复前"counting them as breakpoints reported ~670 'breakpoints' for zero rearrangements"。修复提交 `c974f5f`，2026-09-01。
- `Syn2bANI-paper/data/syntracker_validation/syn2bani/syn2bani_Escherichia_coli_hypermutator.tsv`（2026-08-30 生成）第 2 行：`M1_d136_cloneE10  M1_d136_cloneE10  99.9999 ... synteny_blocks=49  breakpoint_count=939`。**一个基因组和自己比，939 个断点。**
- `results/syntracker_validation/SYNTRACKER_STRUCTURAL_REANALYSIS.md`（09-02）用修复后的 Syn2b 通道重跑：所有 cohort 自比较 = 0，hypermutator *E. coli* 中位 breakpoints = **0**（负对照，符合 SynTracker 的生物学）。文件最后一句："The pre-fix `syntracker_summary.tsv` and the old figures derived from it should not be cited."
- 稿件 Results 第 79 行仍写："*E. coli* hypermutator pairs with ANI > 99.9% show 850–1,130 breakpoints ... *S. rimosus* reaches 2,957 breakpoints" —— 正是 `syntracker_summary_pre_fix.tsv` 里的数（mean 905.7 / max 1128；S. rimosus max 3164）。
- `case_studies/ecoli_o157_fitzgerald_2021/results/triangle.tsv`：`CP062780 vs CP062739`，ANI 99.9999，`synteny_blocks = 57`，`breakpoint_count = 1045`。当前实现（`chain_ani.rs:950-975`）里 breakpoint 只能发生在同一 query contig 上相邻 chain 的转换处，上限 `n_chains − n_chained_contigs = 56`。1,045 > 56，因此该案例研究**不可能**是当前代码跑的。S. aureus（FDA-ARGOS）同理需要重跑。
- GTDB "336 high-AF pairs ... 10 most discordant pairs carry 61–989 SV calls"（Fig. 6）来自 `results/gtdb50k/DISCORDANCE_ANALYSIS.md`，同样在修复前生成。

我用当前 HEAD 的二进制做了对照实验（*E. coli* K-12，`prototype/mg1655.fasta`）：

| query | breakpoint_count | synteny_blocks | ANI |
|---|---:|---:|---:|
| 自身 | 0 | 1 | 99.9999 |
| 1 个 400 kb 倒位 | 2 | 3 | 99.9999 |
| 3 个倒位 | 6 | 7 | 99.9999 |
| 起点旋转 1.2 Mb | 0 | 2 | 99.9999 |
| 打碎成 50 contig、半数反向互补 | 0 | 48 | 99.9999 |
| 1% 随机 SNP | 1 | 2 | 98.9974 |

当前代码行为正确。**结论：稿件里所有 `breakpoint_count` 数值必须用 `≥ c974f5f` 的二进制重跑；"High-ANI pairs hide extensive rearrangements" 一节、Fig. 6、Supp. Fig. S8–S10 目前不成立。** 重跑后 hypermutator *E. coli* 大概率回到 0，这一节的叙事（"ANI 相同但几百个重排"）要重写。

### A2 [致命] ANI 主比较不公平：校准 vs 未校准

稿件（Abstract、Table 1）："On 43,334 held-out GTDB-R207 pairs the calibrated estimator achieves MAE 0.619% against ANIm, compared with 0.957% for skani and 0.977% for FastANI."

三个问题：

**(a) n 不一致。** `results/gtdb50k/GTDB50K_HELDOUT_REPORT.md`：`syn2bani_cal n = 39,903`，skani/FastANI n = 43,334。校准列在 3,431 对（`BELOW_DETECTION`，其中 2,504 在 85–90 带、925 在 80–85 带）上缺失。0.957/0.977 是 skani/FastANI 在 39,903 common subset 上的数。所以"43,334 held-out pairs ... MAE 0.619"字面上就是错的（README 第 121 行和 SUPPLEMENTARY.md 第 45 行倒是老实写了 39,903）。拒答不该是免费的：至少要报告这 3,431 对上 raw 的 MAE（我算了：raw 1.326，FastANI 1.838），或给 coverage–accuracy 曲线。

**(b) 对手没被校准。** 对手的误差几乎全是常数偏差（FastANI 80–85 带 bias −1.83，skani −1.97）。我用稿件自己的 band-holdout 协议在 `s2b_50k.tsv`+`truth_50k.tsv`+`fastani_50k.tsv` 上做了最简单的线性校正：

| 方法 | n | MAE（全部） | MAE（common 39,903） | r |
|---|---:|---:|---:|---:|
| syn2bani calibrated v5 | 39,903 | — | 0.619 | 0.962 |
| FastANI 原始 | 43,334 | 1.045 | 0.977 | 0.980 |
| **FastANI + 1 参数线性校正（band-holdout）** | 43,334 | **0.510** | 0.521 | 0.976 |
| FastANI + 3 特征线性校正（ani, mapped, total） | 43,334 | **0.456** | 0.462 | 0.980 |

分带（common subset）：80–85 带 syn2bani_cal 1.015 vs FastANI+线性 0.421；85–90 带 0.651 vs 0.470。**一个单参数的线性回归就让 FastANI 全面超过 Syn2bANI 的 9 特征 ridge。** skani 的原始文件不在 `results/gtdb50k/`，但其偏差结构相同，结果可预期一致。

**(c) 校准前的估计量在低 ANI 带几乎没有信息。** 同一报告：80–85 带 `syn2bani_raw r = 0.120`（common subset 上 **−0.06**），校准后 r = 0.41；skani r = 0.68，FastANI r = 0.83。Syn2bANI 在 80–85 带的 MAE 优势来自 ridge 把估计拉回带内均值（bias −0.21），不是来自分辨力。审稿人会问：一个 r ≈ 0 的"估计量"加上 9 个特征的回归，是 estimator 还是 ML predictor？Introduction 说"raw estimator is essentially unbiased"只在模拟里成立。

需要做的：所有对手用相同的 band-holdout 线性校正后再比；报告每一带的 r 和 MAE；所有方法在同一 n 上比较；把 3,431 个拒答 pair 的处理写清楚。

### A3 [重大] 标题说"strain-level"，Table 1 说 skani 在 95–100 带更好

- Table 1 held-out：95–99/95–100 带 syn2bani_cal 0.44 / skani 0.32 / FastANI 0.36；90–95 带 0.54 / 0.43 / 0.46。Syn2bANI 只在 80–90（种间）赢。
- Discussion 自己承认"skani ... is more accurate in the near-clonal 97–100% regime"。
- 43,334 held-out 集 95–100 带只有 404 对（0.9%），"strain-level"的评估几乎没有统计力；补的 727 对 high-ANI test set 又是**非代表基因组**、单独抽样，与 held-out 的采样框架不同。
- hybrid 规则（raw ≥ 98% / calibrated < 98%）的 98% 阈值是在评估集上选的（`hybrid_threshold_sweep.tsv`）——这是在测试集上调参。

要么改标题（去掉 strain-level），要么补一个真正的 strain-level 基准（例如同种 ≥ 97% 的几千对，训练集外），并在该基准上诚实地与 skani ≥ 0.2 比。

### A4 [重大] 对手版本过旧

Methods："skani 0.1.0 (0.3.2 for the HPC database-scale runs), FastANI 1.33/1.34"。skani 0.1.0 是 2022 年的预发布版；Nature Methods 论文对应 0.2.x，当前 0.3.x，ANI 回归模型和默认参数都变了。本地 `~/.cargo/bin/skani` 就是 0.1.0。所有 skani 数字须用 ≥ 0.2.1 重跑，并说明是否用了 `--slow`/`-c` 等针对低 ANI 的推荐参数（skani 文档建议 <90% ANI 时调 `-c`）。

### A5 [重大] `struct` 的"环状起点"伪影默认不过滤，且 GTDB/案例研究均未过滤

`--circular` 是 09-04 才加的 opt-in 参数。我用当前二进制把 K-12 起点旋转 1.2 Mb（无任何真实重排）：

```
rot  Translocation  q:3440006-3442598  r:946-4640006  size 2592
```

默认输出一个覆盖 99.98% 染色体的"translocation"，`size` 字段还给出无意义的 2,592。加 `--circular` 后被过滤。但：Fig. 6 的 GTDB "61–989 SV calls"、O157、S. aureus、Syntracker 案例都没有用 `--circular`（case study 脚本只有 H. pylori 用了）。稿件 Methods 应承认 circular 处理是 opt-in，并把所有 SV 计数在开启过滤后重算；更好的做法是默认对单 contig ≥ 1 Mb 的参考自动启用。

### A6 [重大] cagPAI "complete_rearranged" 定义过宽

稿件："287 (54.4%) retained the markers but carried a local inversion or translocation **inside** cagPAI"。用 `case_studies/h_pylori_cagpai/results/cagpai_states_extended_filtered.tsv` 核对 287 个 rearranged 基因组的 `cag_sv_list`：

| 情况 | n |
|---|---:|
| 至少一个 SV 完全落在 cagPAI 窗口（±2 kb）内 | 53 |
| 至少一个 SV 端点落在窗口内 | 154 |
| **所有 SV 都跨越整个岛（岛完整，只是位于一个更大的倒位/易位块内部）** | **133** |

即 46% 的"rearranged"是 100–600 kb 的大倒位把完整的 cagPAI 整体带反了，岛的内部结构未变。"local ... inside cagPAI"不成立。分类应改为：岛内断点 / 岛被大块重排包含 / 共线，三类分开做关联检验。另外过滤后 rearranged 的 SV 跨度中位数 147 kb、75 个 > 200 kb——`--artifact-threshold 0.5` 之下仍有大量可能是起点/复制叉相关的半染色体倒位，需要与 dnadiff 逐一核对。

同时：Results 写"nine-strain panel"，Methods 和 Table 3 写"Eight *H. pylori* 26695-derived genomes"；Song et al. (2026)、Fitzgerald et al. (2021)、B. longum 便秘研究、FDA-ARGOS 四个数据来源**都不在参考文献里**。

### A7 [重大] "raw_inverted_fraction" 在草图基因组上测的是 contig 方向，不是生物学

稿件（Results 第 85 行）把 Syn2b 的 `raw_inverted_fraction` vs dnadiff 的 r = 0.936 当作结构输出的核心验证。但 `results/syntracker_validation/SYNTRACKER_STRUCTURAL_REANALYSIS.md` 自己写："The orientation channel (inverted_fraction) is near 0.5 across all cohorts, as expected for short-read draft assemblies where most pairs are too fragmented for a reliable strand call"；`metric_validation/high_ani_validation.tsv` 里 dnadiff inverted fraction 的**均值是 0.479**。同种 pair 平均一半的比对碱基是反向的，这不是生物学，是每个 contig 的组装链向随机。两个方法高度一致，是因为它们测的都是同一个组装伪影。要证明它测的是生物学，只能用闭合基因组——而 `Syn2b-paper/results/metric_validation/closed_genome_summary.tsv` 显示闭合基因组上 Syn2b 的倒位召回率只有 4/35（13.6%），junction 中位偏差 21.8 kb（`results/closed_inversions/JUNCTION_COORDINATE_REPORT.md` 自评："worse than landmark spacing ... not the ~spacing-level agreement seen in controlled simulations"）。

## B. Syn2b 论文（`Syn2b_Manuscript.md`）

`REVIEW_2.md`（09-06）已经详细指出：Fig. 4 的两个坐标轴都不是标签所说的量（popANI 是输入参数的线性函数并被 clamp 到 [0.9995,1]；synteny score 是两个绘图脚本里各自定义的、工具里不存在的加权和，且其 70%/50% 分量是源码自己弃用的 substitution-load 指标）、§3 的 5,148 个"baseline breakpoints"、Table 4 的 per-pair 时间按 n² 而非 C(n,2) 算（真实值约 2.1×）、`sv_rate_diff` 是死参数、Supplementary Note 2 / Table 4 / Fig. 1–4 不存在、abstract 声称的"real-data popANI–synteny"不存在。**稿件 HEAD（`ab086ce`）早于该审稿，这些一条都没改。** 以下只补充新的发现。

### B1 [致命] "length-weighted" 不是实现的东西

标题、Abstract、§1、§2（`F = Σ_{i∈P} ℓ_i / Σ_i ℓ_i`）、Methods 都把核心指标定义为**长度加权**的比例。源码 `Syn2b/src/synteny/scoring.rs:754-766`：

```rust
raw_inverted_fraction: orientation_mismatches as f64 / informative as f64
```

是**方向翻转的共享 landmark 个数 / 方向可判定的共享 landmark 个数**——按 landmark 计数，不按长度。两者只在 landmark 均匀分布时相等；§5 自己说误差模型的 1.48 系数"reflects spatial clustering of landmarks"，这正是计数与长度之差。分割不变性对计数比例同样成立，所以原理没错，但标题和整篇的指标描述是错的。要么改实现为真正的长度加权（每个 landmark 权重 = 到相邻 landmark 的半间距），要么把全文的"length-weighted"改成"landmark-fraction"。

### B2 [致命] 两个"四酶 panel"

- §1/§3/§4/Table 1/Methods：BcgI + AlfI + BplI + **CjePI**，*E. coli* K-12 上 14,483 tags（3.19/kb），其中 CjePI 9,284。
- Methods §GTDB："Syn2b was run with the BcgI+AlfI+BplI+CjePI multi-enzyme panel"。
- 实际 GTDB 运行：`scripts/run_syn2b_inverted_fraction.py:62  DEFAULT_ENZYMES = "BcgI,AlfI,AloI,FalI"`；`bench_syn2b_struct.py:33` 同；`inverted_fraction_truth_four.tsv` 中位 shared tags 314，与 README "四酶 panel 6,079 landmarks / K-12" 的密度一致，与 14,483 不一致。
- 模拟里的 "CjePI"：`scripts/simulate_rearrangement.py:185-207` 定义为 5'-CCYGA-3'、32 bp、"Type IIG"；Rust `src/enzyme/enzyme.rs:207-211` 和 REBASE 的 CjePI 是 CCA(N)7TC、27 bp、Type IIB。稿件 Methods "CjePI (32-bp tag): recognition motif CCYGA" 描述的不是 CjePI。§4 整段"Why this combination"、"CjePI's 4–8× higher indel sensitivity validates the need for a high-density Type IIG layer"建立在一个不存在的酶上。

要么把模拟全部用 Rust 工具、真实酶定义重跑（REVIEW_2 §C 已建议），要么明确 GTDB 验证用的是 Syn2bANI 的 BcgI/AlfI/AloI/FalI panel 并改写 §4。

### B3 [重大] 抽样描述自相矛盾，且把 dependent variable 当分层变量

Methods："Pairs were stratified ... into identity bands (80–85, ...) using the alignment-based inverted aligned fraction as a proxy for pairwise divergence." 按字面意思是用因变量分层，会让整张 band 表失效。实际（Syn2bANI-paper `scripts/gtdb50k/`）是按 skani 预筛 ANI 分带。改一句话。

### B4 [重大] 闭合基因组结果被写反了

§5："Syn2b detected a median of 4 inversions per pair that were also found by dnadiff (median distance ... 21.8 kb), while dnadiff reported 31 additional ... These numbers are consistent with the sampling model ... reflect landmark density rather than algorithmic error." 底层报告 `JUNCTION_COORDINATE_REPORT.md` 的原话是"Coordinate agreement is worse than landmark spacing: the median matched distance (16 kb) is ~37× the median landmark spacing (~440 bp)"，并建议"Coordinate-level validation on highly rearranged real pairs is not the strongest way to demonstrate Syn2b's accuracy"。召回 13.6%、坐标偏差 37 倍 landmark 间距，不能写成"consistent with the sampling model"。这是目前稿件里**唯一**的闭合基因组（即不受 A7 contig 方向伪影影响）的验证，它是负面的。

### B5 [重大] 主验证的生物学含义（同 A7）

r = 0.936 建立在草图 vs 草图的 43,312 对上，dnadiff inverted fraction 均值 ~0.48。这是一致地测量了组装链向。稿件"fragmentation principle"证明的是**切割**不变性（Supplementary Note 1 假设片段保持方向），而真实组装**丢失**每个 contig 的方向。请在 §2 和 Discussion 明确：fixed-reference inverted fraction 在草图上仅在 contig 方向已知（或经 reference-guided 重定向）时有生物学意义；majority-frame 版本对此稳健但饱和于 0.5。

   assemblies: 54 of the accessions are the GenBank copy, or a superseded
   version, of another accession in the same list. The collection is now
   reported as 67 genomes and 2,211 pairs, and it turns out to be a *negative*
   control for the ANI–structure decoupling rather than an example of it.

Both changed the paper's structural claims materially and in the direction of

accordingly; see **Manuscript Status** in the repository README for the list of
